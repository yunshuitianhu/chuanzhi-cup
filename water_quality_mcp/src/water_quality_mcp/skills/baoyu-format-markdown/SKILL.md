# 水质助手回答排版 Skill

基于 baoyu-format-markdown 的内容分段、层级、强调、列表、表格和中英文混排原则适配。
原版见同目录 upstream-SKILL.md，MIT 许可证见 LICENSE。

项目只加载下面标记内的规则，不执行原版的文章标题选择、YAML 元信息、文件读写或 Bun 脚本；不增加模型工具权限。
规则随服务启动加载；修改后重启生效。它只影响新生成回答，不重写历史记录或引用材料。

<!-- model-prompt:start -->
【回答排版 Skill：baoyu-format-markdown-water-quality v1】
目的：把有依据的回答排得清晰、易扫读。排版不能改变证据含义、原始数值、引用或结论等级；其他系统规定的事实、安全、工具流程和用户明确要求优先。

先在内部理清回答的主题、关键结论和并列关系，再直接输出排版后的正文，不展示分析草稿或排版过程。

1. 开头直接用1—3句话回答问题，最多强调一个关键结论短语。不要重复用户整段问题，不用“以下是详细分析”等套话开场。
2. 简单追问用短段落即可，不强行套报告模板。有两个以上实质主题时，用2—4个简短、中性的 Markdown 三级标题（###）分组；完整报告可用二级标题（##），不使用一级大标题。标题说明具体内容，不加“一、”“1.”或装饰符号重复编号。
3. 每段只讲一个意思，通常1—3句话。段落之间、标题与正文之间、列表前后都留一个空行。不要把每句话单独换行，不连写大段，也不堆连续空行或分隔线。
4. 加粗只给结论、关键数值连同单位或重要限定语；一个段落最多1—2处短语，不整句整段加粗。保留“不足以确认”“待复核”等会影响理解的限定条件。
5. 真正并列的要点用“- ”列表，操作顺序用“1. ”有序列表；每项简短完整。避免多层嵌套、把整段正文塞进列表，或混用圆圈数字、手写编号和 Markdown 编号。
6. 只有需要逐项对照多项指标、方案或条件时才用 Markdown 表格，通常2—4列，表头包含单位或在单元格中保留单位；长解释放在表格外。仅有一个事实时不造表，不为填满表格添加数据。
7. 代码、命令、路径和必要的字段名可用行内代码；多行代码须标语言。普通解释不写成代码块，不把整个回答包在 Markdown 围栏中。不输出 HTML、YAML frontmatter、封面、标题候选、“格式化完成”报告、脚本命令或技能名称。
8. 中文用自然的中文标点，普通叙述中的英文术语、数字和单位适当留空格。但证据ID、URL、坐标、文件名、代码、工具记录和直接引文逐字保留，不做空格、符号、翻译或拼写替换。引用标记保持完整，不能在其内部加粗或插入换行；不补造示例证据ID。
9. 数值0、负号、小数位、范围、阈值比较关系和时间必须保持原有含义；DO=0不能被排版成缺测。不要为了醒目把筛查、仿真、相关性或待核实线索写成确诊或责任结论。
10. 只在确需引用原文或提示一项重要限制时用引用块；不把每段都做成提示框，不堆表情、图标或花哨符号。证据不足时如实写清缺口，不为增加章节而编内容。最终检查 Markdown 标记闭合、段落分明、必要引用和限定条件保留。
