## 1. 本次实现

### 1.1 后端

新增 `POST /api/vision/observe`：

- 只接受当前会话的 `video_frame`（`frame_id + video_revision`）或 `image_asset`（`asset_id + asset_revision`），字段必须与类型匹配。
- 复用 `backend/vision.py` 的真实图片加载、版本校验、尺寸/解码与缓存；不信任客户端提交的图片内容或摘要。
- 调用 `deepseek-flash` 视觉接口，要求严格 JSON：`observations[{visible, where, uncertainty}]`、`not_visible`、`quality_notes`。
- 拒绝未知字段、空白观察项、超长文本、错误 JSON；允许“无可见对象”的空观察列表，但必须由 `not_visible`/`quality_notes` 说明原因；模型返回的 `frame_id` 不被信任，帧号/时间由服务器从实际加载的图片记录填入。
- 返回模型名、来源元数据（不含 base64）、图片 SHA-256、项目/分析/结果版本、问题、观察、限制和耗时；视频帧同时返回确定性抽帧质量（状态、标志、提示、是否可作线索），与模型观察并列而不是互相替代。
- 同一图片摘要 + 问题 + 模型在本会话内缓存**模型解析内容**；命中时按本次已校验图片重新生成来源、帧号、时间和确定性质量，重复请求 `cached=true`，不重复调用模型。
- 调用前后核对项目/分析/结果版本和来源 revision；模型等待期间项目、数据或视频变化时返回 409，不返回成功结果、不写缓存。
- 只接受 `finish_reason='stop'`；超长、内容过滤或缺失结束标记按未完成处理，不写成功缓存。
- 鉴权/网络/超时/格式失败分别返回明确提示；不向调用方透传 SDK 异常原文。无 Key 时返回 400。
- 不写入报告、排查板或项目包；替换视频/清理数据时清空本会话视觉观察缓存。

### 1.2 前端

新增 `VisualEvidence.vue`，并接入：

- 视频页当前帧预览下方；
- 聊天页选中的视频帧或图片附件来源卡下方（默认折叠，点击展开）。

交互约束：

- 选择来源、切换帧或页面挂载都不会自动发送；只有点击“发送当前图片给视觉模型”才请求。
- 显示将发送的来源、帧号/时间、视频或附件版本前缀；问题可编辑，最多 500 字。
- 观察中可“停止等待”，客户端取消请求并明确“服务端可能仍在处理，本次结果不写入项目”。
- 来源/工作区/项目/分析版本变化时丢弃迟到结果；失败显示可操作错误，不伪造观察。
- 结果只在本组件展示：可见观察、位置、不确定说明、未看到内容、确定性抽帧质量、模型画面质量提示和固定限制；不显示 base64。
- 页面明确“不给出浓度、不确认污染源/责任、需人工核对”，不自动写入报告或任务。

- 来源 `image_asset`，图片 SHA-256 前缀 `faa124579ddea696`；
- 响应不含 base64。
- 记录：`docs/validation/vision_evidence_20261029.json`。

这证明结构化端点、真实图片加载和视觉模型链路可用；不是现场污染识别准确率、视频帧真实调用或原生视频能力验证。

## 3. 未完成/限制

- 阶段 B 基础短序列已实现；时间偏移、传感器冲突与非连续选择未接（见阶段 B 文档）。
- 阶段 C 原生视频提供方未接入；当前只支持静态图/单帧。
- 真实模型只验证了一张程序生成图片；视频帧端点由受控替身覆盖，未做真实视频帧调用。
- 模糊/眩光/非水面负例、鉴权失败/超时的真实外部复现未执行；模型质量提示不能替代人工复核。
- 视觉观察不持久化，不进入项目包或报告；需要保留时应由后续任务设计证据保存与引用规则。
- 未做真实浏览器截图走查；前端只通过组件行为测试和生产构建。
- 不宣称水体污染识别准确率、黑臭判断或污染责任认定。
