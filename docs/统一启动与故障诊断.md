# 统一启动与故障诊断

## 推荐入口

在项目目录使用Python 3.12安装锁定依赖：`python -m pip install -r requirements-lock.txt`。在`frontend`执行`npm ci`和`npm run build`，回到根目录执行`python scripts/serve_web.py --check`，通过后执行`python scripts/serve_web.py`。Windows入口为`start_web.cmd`，可用`WQ_PYTHON`指定解释器。

网页与API共用`http://127.0.0.1:5174/`。直接打开或刷新`/chat`、`/charts`、`/river`、`/tech`均应返回网页。`/api/health`返回API健康状态，`/docs`保留接口文档；未知API和缺失资源保持404。仅构建资源公开，不公开项目目录或密钥文件。服务仅监听本机、使用一个worker。

此入口不需要运行Vite预览服务器，不依赖本机8004等历史端口。旧开发入口`uvicorn backend.main:app`保持可用；其根路径仍为API说明。

## 预检与错误

| 提示 | 处理 |
| --- | --- |
| Python未找到/版本过低 | 使用Python 3.12；确认命令对应正确解释器，可用`WQ_PYTHON`指定Windows启动器 |
| 缺少前端构建/构建清单或资源不完整 | 在frontend重新构建；分发时必须包含完整dist和其中的`.vite/manifest.json` |
| 运行依赖缺失或不兼容 | 用启动服务的同一个Python安装requirements-lock.txt |
| 项目目录不可写 | 设置`WQ_PROJECT_HOME`到有写权限的目录，保留原项目备份 |
| 端口不可绑定或已占用 | 指定其它端口；预检不会关闭现有程序 |
| 外部密钥未配置 | 基础分析可用；相应Agent、查询或影像功能不可用或降级 |
| 页面“启动检查失败” | 根据括号内的连接、配置、数据恢复、对话、项目目录或预览阶段排查；修正后点“重新连接” |

`--check`会尝试创建项目目录并短暂写入自动清理的探测文件，确认可写；不保存或覆盖用户项目。端口检查是启动前检查，检查后仍可能被其它程序占用；实际服务启动错误仍以终端日志为准。API导入成功不证明所有可选依赖、外部服务或现场数据均有效。

## RAG和外部服务

RAG依赖ChromaDB、sentence-transformers、本地索引与嵌入模型缓存。首次加载嵌入模型可能需要联网下载，不能把“主服务启动成功”当作“RAG已可用”。可在联网环境运行`python scripts/build_rag_index.py`准备索引，再从技术展示查看真实检索状态。无索引或依赖失败应明确降级，不补造案例。

DeepSeek调用需要使用者自己的配置和可达网络；高德/星图另需对应服务配置。`.env`、原始用户数据与运行项目不随Git发布。`requirements-lock.txt`固定直接依赖版本，仍会解析传递依赖，尚不等于所有系统均可离线安装。

## 验收范围

本项检查单服务路由、真实前端产物、资源缺失/路径隔离、端口冲突、启动阶段提示与重连恢复。跨机器安装及导入/保存/重启恢复的完整交付验证列入任务Q02，现场效果验证仍需独立资料。
