# 全站字号增大验收

> 日期：2026-10-28
> 触发：用户要求“加大系统的所有文字大小”。
> 结论：前端 CSS 的 323 处 `font-size` 与 ECharts/脚本中的 20 处 `fontSize` 统一增加 2px；四页在 320/390/768/1280 与 200% 缩放下无横向溢出，17 项可读性检查通过。未做读屏器或真机验收。

## 1. 改动范围

- `frontend/src/**/*.vue`、`*.css`、`*.js` 中所有显式 `font-size: Npx`：统一 `N + 2`。
- `ChartsView.vue`、`RiverView.vue` 等 ECharts 配置中的 `fontSize: N`：统一 `N + 2`。
- 未用全局 `zoom` 或浏览器缩放模拟字号变化；每个文本仍按原层级单独设置。
- 最小字号从 10/12px 提高到 12/14px；常见正文/控件从 12/13px 提高到 14/15px；页面标题和数字相应增大。
- 移动端导航改为两行：第一行侧栏按钮 + 侧边问答，第二行四个页面标签；标签不再被压缩，超出时在标签行内横向滚动。
- 没有新增字体文件或远程字体；沿用系统字体栈。

## 2. 视觉与布局检查

工具：`tests/browser_readability_acceptance.py`，生产构建，隔离项目目录，Chromium 视口模拟。

| 视口 | 结果 |
| --- | --- |
| 320×740 | 四页无横向溢出；导航两行；工作台 2×2；聊天输入区可见 |
| 390×844 | 四页无横向溢出；导航标签完整；工作台 2×2 |
| 768×900 | 四页无横向溢出 |
| 1280×900 | 四页无横向溢出；工作台 4 列 |
| 1280×800 + 200% 缩放 | 通过可读性脚本检查 |

结果：**17 项通过、0 失败**。证据：`docs/validation/readability_font20261028/`（JSON + 13 张截图）。

补充观察：

- 320/390 下聊天工作区高度固定，空状态的三条建议需要内部滚动；不遮挡输入框，但首屏只能看到部分建议。未把“可滚动”写成“全部首屏可见”。
- 导航第二行在 320 下仍可能横向滚动；这是为了避免继续压缩字号或隐藏页面入口。
- 数字、图例、按钮和表格字号同步增大；图表轴标签由 ECharts `fontSize` 调整，未仅改 CSS。
