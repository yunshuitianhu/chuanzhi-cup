# 第四部分　已知缺陷与局限（**最重要的一节**）

> 本节按"是否已修"分类。**未修的一律列出**，不做美化。
> 这一节是本文档存在的意义 —— 说明文档若不写清这些，就失去了可信度。

## 4.1 仍未修复的缺陷

### ① 水力学的质量不守恒（最严重）

**位置**：`river_model/pure_py_hydro.py`

**现象**：非恒定工况下连续性方程不满足，**残差达蓄水率的 103%**。

**已尝试过的修复**：补上遗漏的水面宽 `B_mid` —— **实验已回滚**，因为残差不变且破坏 Newton 收敛。

**根因判断**：Preissmann 用 `h`（水位）作未知量时是**非守恒形式**的离散，
`∂A/∂t ≈ B·∂h/∂t` 这个近似在**变水面宽**河道中不成立。
单点补系数解决不了，需要**重新推导整个离散**。

**参照事实**：HEC-RAS 用的是同一类格式（1D Unsteady Finite Difference），
质量守恒误差仅 **0.0116%**（实测）。说明问题不在格式选型，在离散写法。

**当前影响**：`hydro_engine.py` 会**强制**把非恒定流交给这个求解器，
所以**潮汐工况的结果不可信**。恒定流工况走 HEC-RAS（若可用）。

**验证状态**：`tests/river_model_验收算例.py` 已把该缺陷固定为一项
**"已知缺陷（不阻塞验收，但需在作品说明中如实标注）"**。

### ② 坐标转换从未生效 → POI 搜索中心有偏移

**位置**：`water_quality_mcp/geo_tools.py`、`backend/routers/trace.py`

**精确表述**（此处纠正一个此前流传的**不准确说法**）：

- `wgs84_to_gcj02` **有被调用** —— 但只被 `gcj02_to_wgs84` 调用
- `gcj02_to_wgs84` **没有任何外部调用方**

因此**结论仍然成立**：坐标转换从未作用于任何实际数据路径。
但"`wgs84_to_gcj02` 从未被调用"这个说法**不准确**，本文档更正之。

**后果**：高德要求 GCJ-02 坐标，而监测数据是 WGS-84，
**POI 搜索中心存在约 100~500 m 偏移**。

**当前处置**：不改这个行为，只在 `/api/trace/multi-source` 的响应里
如实标注，避免使用者误以为是精确点位。

### ③ 潮汐振幅表 8 个键不可达

**位置**：`river_model/regional_defaults.py`

`TIDAL_AMPLITUDE_BY_REGION` 有 8 个具体河口键（珠江口 0.80 / 长江口 2.50 /
杭州湾 3.50 / 闽江口 2.80 等），但**全库唯一读法是取 `["default"]`**，
8 个键**永远取不到**。

**后果**：长江口、杭州湾、闽江口的潮汐河道振幅会被低估 3~4 倍。

**为什么没修**：要走通这些键需要一个"坐标/名称 → 河口"的匹配器。
珠三角内各分河口（珠江口/伶仃洋/虎门/磨刀门/崖门）**空间高度重叠**，
仅凭 bbox 难以可靠区分，**误判反而比不判更差**。这是**已知局限，不是遗漏**。

### ④ CFL 判据用了 `np.max(u)` 而非 `np.max(np.abs(u))`

**位置**：`river_model/wq_engine.py:334`

```python
n_sub = max(1, int(np.max(u_now) * dt_s / dx) + 1)
```

若流速出现负值（涨潮倒灌时会发生），CFL 判据会被低估。
**当前流速范围触发不到**，属潜伏缺陷。

### ⑤ 卫星宽度估计的结构性假阳性

**位置**：`river_model/satellite_width.py:257`

```python
dark_threshold = np.percentile(gray, 30)  # 使用 30% 分位数作为暗阈值
```

总把**最暗的 30%** 判为水体 —— 影像里若无水体，仍会强行圈出 30%。
属结构性假阳性。该模块标注为"实验性功能"。

### ⑥ 配置双单例

**位置**：`water_quality_mcp/analysis_config.py`

- `get_config()` 管理 `_DEFAULT_CONFIG`（第 215/222/228 行）
- 模块级另有 `DEFAULT_CONFIG = AnalysisConfig()`（第 233 行）

两者是**独立实例**。全库**无人调用 `set_config`**，故当前无实际影响，
属潜伏隐患。**改动零收益、风险非零，建议不动。**

### ⑦ `test_smoke.py` 的路径错误

**位置**：`test_smoke.py:45`

查找 `苗圃杯/无人船智能水质监测分析和因果溯源样本数据/河道巡航走航样本数据.xlsx`，
而样本文件实际在上一级。

**后果**：第 3 项（黑臭检测）与第 5 项（图表生成）被 `if df is not None`
**静默跳过**，连计数都不进 —— "4 总计"是虚的。
**修复前不要把它当作可信的回归基线。**

**位置**：`river_model/osm_river_lookup.py:68`

## 6.5 本机环境的三个特性（会干扰调试）

1. **Vite 只监听 IPv6 `[::1]:5173`**，`127.0.0.1` 访问不到
2. **curl / urllib 默认走系统代理**，访问本地服务需 `--noproxy '*'`
3. **端口会堆积无法回收的残留监听套接字**：`netstat` 显示 PID 在 LISTENING
   但进程已不存在、`taskkill` 报"找不到进程"。
   **表现为改了代码却不生效**，且不影响 HTTP 200 返回，极具迷惑性。
   **换端口是最快的解法。**
