# 走航时空匹配与延迟排放改进记录

日期：2026-10-18。继续正演模型第一阶段，补齐后续单源反演需要的时间控制和观测接口。

## 本次修复

1. **排放时刻**：新增 `source_start_h`，相对模拟起点计时。按排放窗口与模拟时段的真实交集注入负荷；排放尚未开始时注入为零，未覆盖完整排放时不注入整笔负荷。在排放起止边界处分步，避免将负荷提前摊入前一时间步。
2. **输出时刻**：积分步长和输出间隔分开。默认每 60 秒保存，半小时有 31 个时间点，修复旧实现可能只保存首尾两帧的问题。内核支持 `output_times_h` 指定观测时刻，首尾和模拟范围内的排放边界也会保留。输出数量设有上限。
3. **逐点时空匹配**：新增 `river_model.observations.sample_water_quality`，对每对 `(time_h, chainage_m)` 作双线性插值，保持观测顺序，支持氨氮、CBOD、DO、硝态氮。拒绝越界、缺失组分、非法坐标和非有限浓度；DO=0 保留。插值不会提高原始模型分辨率。
4. **剖面查询**：现在按请求时刻插值；超出模型时段返回错误，避免返回最近一帧并当作请求时刻。
5. **时间覆盖**：多帧水动力场必须覆盖水质模拟时段，不能静默延长末帧。单帧按恒定场使用，并在元数据中明示。修正结果类型中将小时误写成秒的注释。
6. **工程展示**：Web 页面和公共工具参数支持排放开始/持续时间。响应、报告证据和导出元数据保留实际注入量、实际计算桩号、源位置离散距离；情景名称包含排放时间和持续时长，避免不同排放时间相互覆盖。
7. **图表**：时空图中原先固定在总时长 10% 的横线被错误注释为源位置，现改成实际计算桩号的竖线。色标显式使用中文字体，流量上标用数学文本，修复本次样例导图中的缺字警告。

## 使用方式

Web 河道页设置“排放开始 h”和“排放持续 min”；均为情景输入，不能当成已识别的现场排放。

内核的观测接口示例：

```python
from river_model.observations import sample_water_quality

# 每一行观测独立使用它自己的时间和桩号；时间单位小时，位置单位米。
predicted = sample_water_quality(result,
    times_h=[0.12, 0.17, 0.21],
    chainages_m=[900., 950., 1010.],
    constituent='ammonia')
```

如需在真实观测时刻直接保存计算结果，可向 `solve_water_quality` 传入 `output_times_h`。
调用方必须先确认模拟时间原点、河道上下游方向和 GPS 到模型桩号的映射。本次没有自动把走航累计航程当作河道桩号，也没有把整趟走航当作同一时刻的剖面。
