## 1. 相同画面的不同帧共用整份结果

**根因**：缓存键只有图片 SHA、问题、模型和视频版本，没有帧身份；缓存值却包含来源、帧号、时间和确定性质量。相同像素的第 1/3 帧命中同一缓存，返回旧帧号、时间与质量。

**修复**：
- 缓存只保存**模型对像素内容的解析**（observations/not_visible/quality_notes）、耗时和首次观察时间。
- 缓存键改为 `version + 图片 SHA + 问题 + 模型`，不再绑定帧/项目。
- 每次命中都用本次已校验图片重新生成来源、帧号、时间、确定性质量、项目和分析/结果版本；观察内容可跨同像素帧复用，来源不串用。

**回归**：`test_identical_pixels_in_different_frames_keep_each_frame_source_and_quality`。第 0/2 帧纹理相同、第 2 帧人工排除：模型只调用一次，第二结果 `cached=true`，但来源帧为 2、时间 10s、质量 `needs_review/manual_exclusion`，观察项帧号为 2。

## 2. 请求期间项目/数据变化，旧图片标上新项目版本

**根因**：路由使用 `get_session`，模型等待期间可并发切换项目、替换视频或更新分析；返回时直接读取实时会话版本，导致来源属于旧视频、项目/版本属于新工作区。

**修复**：
- 调用前捕获作用域 `(project_id, analysis_revision, results_revision)` 和来源身份。
- 加载图片后再核对一次；模型返回后重新核对作用域与来源（视频 revision 或图片附件哈希）。
- 任一变化则返回 409“项目、数据或视频在观察期间已变化，本次结果未采用”，不写缓存。
- 前端原有 signature 继续丢弃本页已知的迟到结果；后端不再生成错误标记的成功响应。

**回归**：`test_scope_change_during_model_call_is_rejected_and_not_cached`。模型替身内切换项目、递增分析版本并替换视频：返回 409，缓存为空，模型只调用一次。

## 3. 未检查模型结束原因

**根因**：只解析 JSON，没有检查 `finish_reason`；`length`/`content_filter`/缺失结束也能成为成功观察并写入缓存。

**修复**：只接受 `finish_reason == 'stop'`；其余返回 502“视觉模型输出未完整结束”，不解析成功、不写缓存。与主 Agent 的完成校验一致。

**回归**：`test_empty_observations_with_reasons_are_accepted_but_incomplete_finish_is_not`。`length` 与缺失结束均拒绝；空观察列表但带 `not_visible` 原因仍允许（前端显示无可见对象）。

## 4. 空间证据规则改变后旧检测仍标为当前（遗留 P1）

**根因**：空间观测掩码修复改变聚类/支持度语义后，`DETECTION_VERSION` 与 `EVIDENCE_VERSION` 未更新，旧快照不会通过现有过期机制要求重算。

**修复**：
- `DETECTION_VERSION`：`screening-support-v2` → `screening-support-v3`。
- `EVIDENCE_VERSION`：`evidence-2026-10-25-v9` → `evidence-2026-10-29-v10`。
- 旧检测/报告由现有 `detection_outdated`、`bundle_status` 和结果警告标记过期；不补造旧热点。
- 恢复旧项目时若检测/证据版本不符，`publish_snapshot` 调用 `invalidate_report`，把 `analysis_done` 置 false、状态置 `stale` 并清空旧综合摘要；历史消息正文保留。

**回归**：`test_restoring_old_detection_marks_completed_report_stale`；旧项目探针从 `detection_outdated=false/current/analysis_done=true` 变为 `true/stale/false`。

**影响**：已保存的旧检测与证据需要重新运行检测/分析；这是有意失效，不是数据丢失。

## 5. 河道页失败/参数变化未同步全局状态（遗留 P2）

**根因**：`refreshModelStatus()` 只在接受成功结果时调用；后端失败或参数变化导致结果被丢弃时，后端可能已经撤销旧结果并推进 `results_revision`，前端仍持有旧版本。

**修复**：`runInit/runHydro/runPollution` 在 `finally` 中按原请求的 workspace/project/版本 guard 调用 `refreshStatus()`；成功结果仍只在 `request.matches()` 时局部显示，失败/丢弃结果只同步状态，不覆盖新草稿或新请求。

**回归**：`riverRequestState` 新增“参数编辑后丢弃的成功仍刷新全局状态”；原有失败、参数编辑失败、成功和项目切换用例保持通过。
