## 二、按差距性质分三类

### A 类：**原理性差异**（不是"没做"，是"选了另一条路"）

**反演溯源（文档的核心，标为"核心"那一行）**

| | 文档推荐 | 本仓库 |
|---|---|---|
| 原理 | 从**浓度时间序列**数学反推源参数 | 从**外部数据库**查附近污染源 |
| 数学 | 贝叶斯-MCMC / DREAM / WOA-LSTM | 加权融合 |
| 输出 | 源位置、释放时间、排放量 + **后验分布** | 候选列表 + 权重 |
| 前提 | 浓度序列足够长 + 正演模型可信 | 网络 + API Key |

**这两条路不可互相替代。** 文档路线能回答"是谁、什么时候、排了多少"，
本仓库路线只能回答"附近有哪些登记在册的疑似源"。

### B 类：**真正的缺口**（值得评估是否补）

| 缺口 | 补的代价 | 补的价值 |
|---|---|---|
| **异常检测** | 低（IQR / z-score，几十行） | 中——质控是文档列的模块之一 |
| **去噪** | 低（滑动平均 / 小波） | 低-中 |
| **预警/报警** | 低（阈值触发 + 前端提示） | **中高——系统完整度，文档明确列了** |
| **Kriging 插值** | 中（需 pykrige） | 中——地图可视化加分项 |
| **不确定性量化** | 中 | 中 |

### C 类：**不建议补**（成本远超收益）

| 项 | 原因 |
|---|---|
| EFDC / MIKE 21 / Delft3D | 重量级依赖，MIKE 是商业软件 |
| 贝叶斯-MCMC 反演 | 需可信的正演模型 —— 而本仓库水动力**质量不守恒 103%**，反演建立在它上面没有意义 |
| PINN / 知识图谱 / 荧光指纹 | 需专门数据（荧光需光谱仪），与现有数据不匹配 |
| LSTM 代理模型 | 需大量训练数据；本项目只有一个 1805 条样本 |

## 三、最重要的一条结论

> **文档的核心（贝叶斯反演）建立在一个本仓库尚不具备的前提上：可信的正演模型。**

反演的逻辑是"给定观测浓度 → 调用正演模型 → 比对 → 调整源参数"。
如果正演模型本身质量不守恒（当前纯 Python 求解器残差 103%），
反演出来的源参数没有意义 —— **误差会被归因到源参数上，而不是模型上**。

**所以顺序应该是**：先把正演做可信（HEC-RAS 已验证可达 0.0116%），
再谈反演。这也解释了为什么之前决定"暂不启用 HEC-RAS 非恒定流"是合理的 ——
但那是**在补反演之前必须先解决的前置**。

## 五、本轮比对中的两处误报（记录以免重蹈）

初次检索时两条命中是假的，逐条打开才排除：

1. **「预警」命中 5 个文件** → 全部是 `logger.warning(...)`，**项目没有预警系统**。
   仅凭关键词计数会得出"已有预警能力"的错误结论。
2. **`analysis.py` 命中 "neural"** → 实际是 `from sklearn.cluster import DBSCAN`，
   无监督聚类，与神经网络无关。

**教训**：关键词检索只能用来定位，**判定"有/无"必须打开看**。
