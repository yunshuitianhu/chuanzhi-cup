# Q06 RAG固定评测与融合检索验收

开发与评测日期：2026-10-22；整理完成：2026-10-23。评测对象是当前本地整理资料的查找、片段覆盖和受约束问答。标注及回答复核由Agent完成，未经过独立专家复核，不能据此报告现场污染检测准确率、治理效果或责任识别能力。

## 固定集与实验口径

- 当前29份Markdown整理资料切为147个分块。对既有索引逐块核对正文与来源文件后，将原向量复制到工作目录的隔离索引；不重建或清空用户原索引。不同资料可能描述同一工程，29份不等于29个独立工程或147个案例。
- 在查看基线结果前固定30道问题及目标文件、原文行、要点文字；10道开发题（8道有资料、2道缺资料）用于改进，20道留出题（16道有目标资料、4道缺资料）在实现选定后才计算指标。
- 问题主要是指定资料中的方法、规模与数值查找；这是有限的资料定位任务，不能代表任意开放领域问题。相关文件标注也不是专家完成的完整相关性判断，因此报告目标文档命中、MRR与要点覆盖，不宣称完整检索精确率。
- 冻结集位于 `evaluation/rag/questions.json`，保留源文件指纹前缀及逐条依据。原向量基线在改动前已捕获；最终重跑的30道题分块排序均与捕获结果相同。候选检索实现先在开发集选定，再执行留出评测，未按H02/H14失败项继续调参。
- 后续只有过滤条件文档示例修正，无检索逻辑变化；通过反向替换该注释并比对冻结时文件哈希确认。原始24次模型回答与严格检查结果完整保留；Markdown格式宽容检查是另行补充分析，不覆盖原结果。

## 实现

1. 现有向量召回与中文双字词面BM25融合，以RRF合并排名；没有新增在线服务、额外重排模型或依赖某条河流的名单。中文双字和英文/数字词元来自查询及索引文本，标题和水体类型用于查找资料。
2. 按 `source_file` 合并同一文件的分块，避免多个分块占满“案例数”。再从该文件选择一个针对问题细节的片段，并保留一个融合召回片段，最多两个、不重复。不同文件描述同一工程时仍可能同时返回，未宣称完成语义级工程去重。
3. 返回实际索引分块ID、来源文件、来源说明、章节与原文，每个片段最多1000字符并明确截断。300字符摘要继续兼容原字段，但不能据摘要补造未出现的具体数值。资料无已核验原始发布链接时明确说明，不生成虚构URL。
4. Web、Agent、MCP和报告共用检索内核。Agent的RAG返回使用独立12000字符上下文预算，超预算时减少案例并保留完整JSON及片段，说明实际保留数量；其它工具的原预算不变。
5. 单次向量候选最多80个，词面扫描最多2000块。超限显式回退到有界向量来源合并，并在返回的检索方法字段标明；本次147块未触及该上界。过滤条件同时作用于两路检索，标量元数据用标量匹配，不把逗号字符串当数组过滤。
6. 搜索API使用有界严格请求模型，查询1~1000字符、返回数1~10，错误类型或非整数返回422，空白查询400。无匹配筛选结果不再误称整个库为空。技术页显示向量余弦数值、原文核对和离线结果，取消容易被误读为概率的百分比徽标。
7. 引用规则进入统一证据规则v4：资料记载不冒充本次实测，不以相似度认定责任，缺所问事实或时段须说明。规则变化后旧证据按原机制标为过期，不追补历史引文。

方法背景参考：[Microsoft的RRF说明](https://learn.microsoft.com/en-us/azure/search/hybrid-search-ranking)、[Sentence Transformers的召回与重排说明](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)、[Chroma元数据筛选文档](https://docs.trychroma.com/docs/querying-collections/metadata-filtering)。本实现采用词面与向量排名融合及文件内片段选择，没有部署CrossEncoder。

## 留出结果

正例指标只统计16道有目标资料的问题，片段覆盖分母为20个预标注要点；缺资料题不混入正例分母。

| 指标 | 原向量检索＋300字符摘要 | 融合检索＋原文片段 |
| --- | --- | --- |
| 目标文档前1命中 | 11/16（68.75%） | 15/16（93.75%） |
| 目标文档前5命中 | 14/16（87.5%） | 16/16（100%） |
| MRR@5 | 0.7417 | 0.9688 |
| 标注要点片段覆盖 | 9/20（45%） | 18/20（90%） |
| 返回结果的来源文件去重比例（全部留出题） | 82% | 100% |

另选留出集中的5道有资料题和3道缺资料题，三种上下文方案各实际调用DeepSeek 8次，共24次；所有调用以stop完整结束，无请求失败。统一模型、提示、温度0、最大12000字符上下文预算。原方案保留300字符摘要，仅为公平检查引用而补上实际分块ID；新方案提供最多两个1000字符片段，实际上下文长度不同，因此比较的是整条检索/片段管线，不能把增益全部归因于排序。

| 回答检查 | 无检索上下文 | 原方案 | 新方案 |
| --- | --- | --- | --- |
| 回答到目标事实（Agent逐条复核） | 0/5 | 1/5 | 3/5 |
| 全部要点有严格匹配引文 | 0/5 | 0/5 | 2/5 |
| 去除Markdown粗体/代码标记后全部要点有匹配引文 | 0/5 | 1/5 | 3/5 |
| 严格匹配的引文条数 | 无引文 | 0/1 | 6/7 |
| Markdown格式归一后的引文条数 | 无引文 | 1/1 | 7/7 |
| 缺资料题保留判断 | 3/3 | 3/3 | 3/3 |

“原文匹配”忽略空白与全半角，不改数值、单位或比较符；格式补充检查只去除配对Markdown粗体与行内代码标记。它们都不等于完整语义蕴含认证。无检索方案遵循同一个“仅按提供资料回答”提示，未给资料时拒答是预期行为，不能据0/5推断模型自由问答能力。

## 保留的失败

- H02：找到了垃圾渗滤液资料，但未返回“出水22 mg/L”所在效果片段。
- H14：找到了杭州横一港资料，但未返回“4.2 mg/L”所在效果片段。
- 两项回答正文说明没有所问具体记录，却将结构化 `answerable` 设为true，均计为未完成回答；相关引文能匹配其他原文，也不能计作回答成功。不能只展示7/7格式匹配而声称回答全对。
- 原方案H01和新方案H08各有省略Markdown粗体的引用格式差异；数值未改，保留严格失败并另外报告格式补充结果。
- 原始发布内容及来源说明尚未逐条独立核验，无法把本地资料中的历史数值视为已经验证的环境事实。引用自动检查还不能保证每句因果解释正确。
