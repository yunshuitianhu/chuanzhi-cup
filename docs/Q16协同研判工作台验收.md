## 1. 实现

在 `frontend/src/views/ChatView.vue` 顶部增加紧凑工作台条，四项对应任务要求的链路：

| 项 | 来源 | 动作 |
| --- | --- | --- |
| 数据 | `status.has_data/rows/data_identity` | 跳到「数据与示例」；无数据时显示“等待数据” |
| 当前问题 | `questionContext`、`textQuestions.pendingMain`、`chatDraft` | 聚焦输入框；自动分析不伪造用户问题 |
| 分析进度 | `agentRun` 阶段/状态、`status.analysis_done/has_detection` | 运行中查看进度；有数据未筛查时开始自动分析；已筛查查看图表 |
| 证据 · 下一步 | `status.black_spot_count`、`has_detection` | 打开现有排查板；无数据时跳到示例入口 |

同时：

- `DataPanel` 的示例区增加 `id="data-samples"`，工作台可直接定位。
- `AgentProgress` 外层增加 `id="agent-progress"`，运行中可从工作台回到进度。
- 工作台不新建第二套状态；所有值来自现有 store 和会话/revision。
- 保留四页导航、主聊天、Q13 上下文卡、Q14 划词/侧边问答、Q15 结构化卡片与排查板。

## 2. 真实流程（成功与失败重试）

示例均为 S01 V2（1801 行、`synthetic`），生产构建，真实 DeepSeek 服务。

### 2.1 RAG 成功路径

环境：5188，完整共享依赖 + 隔离的 `.rag_index` 副本（29 份资料、147 块）。

1. 载入 S01：`1801 条记录 · 仿真 / 未提出 / 已完成基础筛查 / 0 个预警点`。
2. 点击「开始自动分析」：实际执行 **29 秒、12 次工具调用**，工作台显示「本轮已完成」。
3. 报告生成，未触发黑臭预警；RAG 检索成功，报告引用真实证据 ID
   `黑臭水体\济南小清河黑臭水体综合治理案例.md_3`，并说明是本地资料、非本次实测。
4. 显示 3 张待确认研判卡片（草稿，未写入排查板），下一步复测建议可见。

截图：`docs/validation/q16_rag_success_1280.png`。

### 2.2 缺依赖失败与重试

环境：5187，干净 CI venv（缺 `chromadb`/`sentence_transformers`）。

1. 第一次自动分析：26 秒、11 次工具调用，报告生成，但治理案例检索失败；工作台显示「上轮部分完成」。
2. 点击「从当前数据重新执行上一请求」：第二次运行实际执行，运行中显示「等待模型响应」，结束后仍为「上轮部分完成」；重试入口保持可见。
3. 报告保留缺测、配准未设置、视频跳过和 RAG 失败说明；没有伪造案例引用。

截图：`docs/validation/q16_failure_retry_1280.png`、`q16_auto_analysis_partial_1280.png`。

重试没有因环境缺依赖而变成成功；这是如实结果。
