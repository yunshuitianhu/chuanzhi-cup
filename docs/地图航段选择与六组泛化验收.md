# 地图航段选择与六组泛化验收

日期：2026-11-05。

用户反馈只有一份数据能在地图播放。按实际上传解析流程复现：S01–S06均含往返巡测，原映射入口拒绝把累计航程作为河道桩号。前次只验证单向轨迹及长度覆盖，没有覆盖这些数据的完整使用流程。

## 通用改动

新增地图情景航段选择流程。从当前解析数据中按有效原始GPS和完整时间切成连续段；对返回审核警告的区段，在最远行程位置分开，再次经过同一轨迹审核；建议最长的有效候选。候选中不连接缺失GPS的两侧，不读取固定样本、河名、地图坐标或隐藏污染源真值。

播放器中可以生成候选、调整起止记录、反转方向，并明确确认作为本次假定情景的上游→下游后应用。后端根据当前数据重新生成参考线，不直接相信浏览器提交的坐标；数据版本及项目不匹配返回409。配置随既有项目字段保存，恢复时重新核验。配置用于地图显示，不代替观测与模型的逐点时空配准。

原来的拒绝检查保持：整段往返不能直接映射；地图未覆盖范围仍留空；无GPS不能补造地图位置，需要提供独立参考线。用户确认的航段方向不证明真实水流方向。

## 实际验证

`tests/test_playback_reference_generalization.py`包含3个测试方法：其中一个按子用例分别执行全部6份真实CSV的生产解析、HTTP初始化、水动力、污染正演、航段建议/确认、地图查询、反向航段、过期版本拒绝及项目包往返恢复。使用不同长度600/700/800/900/1000/1100 m的手工情景，均为12水动力断面及2倍水质网格，返回23个已映射水质节点。地图配置前后浓度、时间和桩号数组逐项一致，监测表不变。

另外两个方法检查三组全新坐标（北美、南半球、赤道）及GPS缺段，和无GPS、损坏配置的拒绝行为。新坐标检查不读取样例ID，候选不跨越缺失记录。

`tests/serve_map_generalization_fixture.py`在临时项目目录恢复上述6组真实求解后的仿真包；`tests/browser_map_generalization.py`在隔离浏览器逐份操作真实Vue界面：生成候选→确认方向→应用→地图加载→跳到扩散峰值。6组地图和渐变画布均可见，没有页面错误。此次浏览器底图在本地替换为纯色瓦片，外部请求全部拦截，因此这6组验收不声称完成卫星水面配准或外部瓦片可达性验证。真实卫星覆盖层此前的验收记录见《地图渐变扩散播放验收》。

检查结果：新增3个测试方法（含6组实际正演及3组新坐标子用例）、原地图接口19项、走航配准19项通过；前端完整类型检查、404项测试和构建通过，忙碌表单控件调整后重新构建通过。离线字段检查已执行分支匹配，视频和河道分支仍按既有脚本跳过；既有泛化21项通过。按code-review skill复核配置优先级、失效会话响应、空坐标、恢复与源数据隔离，没有发现阻断项。

部署时原5174/5176无监听进程，未终止用户服务。新版在5174启动，沿用原项目目录，健康接口正常；5184隔离验收服务已停止。本轮没有改写已有用户项目或原始样例。

本机详细结果在 `output/map-generalization-six.json` 与 `output/map-generalization-ui/result.json`。这些是受控仿真下的功能泛化验证，不代表任意轨迹都能自动识别正确河道中心线，也不是现场溯源准确率或多源反演验收。

## 同日修复：图表页直接显示自动情景预览

用户在S03图表页再次看到“未定位”的示意图。原因是上一版仍把生成和确认航段作为显示地图的前置操作，六组测试也只验证了点击确认后的路径，没有验证用户直接打开页面的路径。

现在：没有显式配准或用户指定地图航段，且整轨迹不能直接映射时，播放器自动读取已审核单向候选，直接生成地图情景预览。通过参考线球面长度插值真实GPS，未覆盖节点留空。元数据明确标为 `automatic_scenario_preview_unconfirmed`，页面提示实际水流方向尚未确认。该分支不设置任何用户确认、不写 `river_ui`、不更改模型和逐点配准；已有显式配置继续优先，损坏显式配置不会被悄悄覆盖。

验证：

- 六组真实正演接口测试增加断言：未操作配置时地图已经可用，元数据为自动未确认预览，服务器未写入 `playback_reference`。配置前后模型数组仍逐项一致。
- 浏览器验收改为直接打开 `/charts`，完全不点航段生成或确认按钮，直接等待地图并播放峰值。S01–S06均通过，报告明确记录 `route_selection_clicks: 0`，没有页面错误；这六组仍使用隔离测试底图。
- 原地图19项、配准19项、六组泛化所在3个测试方法通过。旧“往返必定关闭地图”断言更新为“严格整轨迹配准仍拒绝、情景预览明确未确认、缺失GPS不跨接、用户显式配准仍优先”。前端404项测试、类型检查、构建通过；离线字段检查执行分支匹配（既有视频/河道分支仍跳过），泛化21项通过。
