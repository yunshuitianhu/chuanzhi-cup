## 二、提案 A：HEC-RAS 可选化（消除可复现性隐患）

### 背景

用户担心"HEC-RAS 只能在我本机跑，别人无法复现"。**实测结论：担心方向对，但实际风险比想象的小。**

| 检查项 | 实测结果 |
|---|---|
| 没有 HEC-RAS 时会不会崩 | **不会**。`detect_engine()` 失败 → 返回 `pure_python`，完整降级 |
| `import` 时是否依赖 pywin32 | **不依赖**。`win32com.client` 是函数内惰性导入 |
| 前后端启动是否要求 HEC-RAS | **不要求** |

**所以评委不装 HEC-RAS 也能跑通系统。** 但有两个真问题：

### 问题 1：路径写死

```python
def is_hecras_available() -> bool:
    path = r"D:\my_HEC-RAS\Ras.exe"     # ← 只对这一台机器成立
    return os.path.exists(path)
```

别人就算装了 HEC-RAS，装在别处也检测不到。

### 问题 2：文档没说明这是可选依赖

读代码的人无法判断"没有它行不行"。

### 方案

| 事项 | 做法 | 成本 |
|---|---|---|
| 路径改环境变量 | `HECRAS_EXE` 环境变量，带默认值；沿用项目既有的 `.env` 机制 | 5 分钟 |
| README 加"外部依赖（可选）"一节 | 写明：缺失时自动降级到内置求解器，不影响功能 | 10 分钟 |
| 技术文档如实说明 | 这也是"AI 技术选型理由"的一部分 | 交付时 |

### 建议的定位

```
默认路径：纯 Python 求解器        → 评委零依赖可跑
增强路径：装了 HEC-RAS 自动启用   → 本机/视频里展示更优结果
```

**现状恰好就是这个设计，只需把它说清楚。**

> 补充理由：官方提交要求里**没有"必须使用某种数值模型"这一条**。
> 要求的是代码规范、Git 历史、README、环境配置、视频、文档。
> **HEC-RAS 用不用不是评审点，"能不能跑起来"才是。**
