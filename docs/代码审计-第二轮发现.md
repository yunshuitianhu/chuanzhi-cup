| 同上 | `严重程度` | `内梅罗等级` | 恒空 |

| `app.py:653-675` 交叉印证说明 | `correlation_pairs` / `correlations` | `相关系数矩阵` | 相关系数信息全丢 |

## B. 已确认的功能缺陷（第二轮新增）

### B.1 高德逆地理识别河道：整条降级链从未生效 ✅ **实测**

`parameter_estimator.py:475-534`

```python
from water_quality_mcp.src.water_quality_mcp.geo_tools import reverse_geocode
geo_result = reverse_geocode(center_lat, center_lon, self.amap_key)
if geo_result:
    address = geo_result.get("address", "")   # ← 对字符串调 .get()
```

`geo_tools.reverse_geocode` 返回 `json.dumps({"地址":..., "省份":...})` —— **字符串**，且键名是中文。

实测：`AttributeError: 'str' object has no attribute 'get'`，被 `:533-534` 的 `except Exception: pass` 吞掉。

**双重错误**：类型不对 + 键名不对。后果是"高德逆地理 → 提取河道名称"这条 Layer 2 路径完全失效，河道识别只剩 OSM 与已知库两条路。

### B.2 演示动画在无高德 Key 时 JS 报错 ✅ **源码确认**

`build_animation.py:292`

```javascript
L.marker([srcLat,srcLon],{icon:srcIcon}).addTo(map).bindPopup(
  '<b>主源:'+nearbyFactories[0].name+'</b>...')
```

`nearbyFactories` 仅在 `if amap_key:`（`:76`）时才有内容，否则为 `[]`。
`[][0]` 为 `undefined`，取 `.name` 抛 `TypeError`。

该行位于脚本顶层，**其后的热力图层创建（`:296`）不会执行** → 动画页面失效。

而 `nearbyFactories` 为空正是"未配置高德 Key"这一常见场景。

### B.3 河床坡度方向反了 ✅ **实测**

`cross_sections.py:114`

```python
bed_el = bed_elevation_avg_m - bed_slope * (channel_length_m / 2.0 - chainage)
```

实测（3.2km / 0.0001 坡降）：

```
断面 0  (桩号    0) 河底 -2.1600 m   ← 上游
断面 10 (桩号 3200) 河底 -1.8400 m   ← 下游
河底沿流向抬升 0.32 m
```

正确应为上游高、下游低。**函数自己的 docstring 写着"上游河底高程略高"** —— 代码与自身注释矛盾，说明是敲错了负号。

正确写法：`bed_elevation_avg_m - bed_slope * (chainage - channel_length_m / 2.0)`

### B.4 潮汐振幅地区查表是摆设 ✅ **实测**

`parameter_estimator.py:155`

```python
tidal_amp = TIDAL_AMPLITUDE_BY_REGION.get("default", 0.8)
```

`regional_defaults.TIDAL_AMPLITUDE_BY_REGION` 有 8 个地区键（珠江口 0.80 / 长江口 2.50 / 杭州湾 3.50 …）+ `"default"`，但代码**只查 `"default"`**。
另有 `:859` 直接写死 `tidal_amp = 0.8 if is_tidal else 0.0`。

后果：无论在哪个河口，潮汐振幅恒为 0.8 m，地区表完全未使用。

### B.5 集水面积恒为 122.8，自动检测流量对所有河道都相同 ✅ **实测**

`parameter_estimator.py:144 / 202 / 856`

```python
catchment = (known or {}).get("catchment_area_km2", 122.8)
```

`regional_defaults.KNOWN_RIVERS_GD` 共 9 条河道，**无一条含 `catchment_area_km2` 键**（实测 0/9）。
故 `.get(...)` 恒返回 122.8 → `estimate_discharge(122.8) = 3.34 m³/s`，
而 `config.py` 记录的雅瑶多年平均流量是 **6.9 m³/s**。

后果：自动检测模式与传统模式的流量相差一倍，且这个值经 `tools.py:158` 直接报给用户。

### B.6 经纬度各自独立 dropna，导致行错位 ✅ **源码确认**

`parameter_estimator.py:611-612`

```python
lats = pd.to_numeric(df_tmp["lat"], errors="coerce").dropna().values.astype(float)
lons = pd.to_numeric(df_tmp["lon"], errors="coerce").dropna().values.astype(float)
```

若纬度列第 3 行为 NaN、经度列第 7 行为 NaN，两个数组长度不同**且行不再一一对应**。

- 长度不同时：`_haversine` 广播失败 → `ValueError` → 冒泡到 `tools.py:98` 的 `except Exception` → 用户看到"自动检测失败"，全部参数静默换成默认值
- 长度恰好相同时更危险：**不报错**，但河长、中心点、OSM 轨迹匹配全部基于错位的点对

同仓库 `geo_mapping.py:78-80` 用的是正确写法（联合掩码 `valid = ~(np.isnan(lats) | np.isnan(lons))`），可确认是疏漏。

### B.7 水质模型 CFL 子步长对反向流失效 ✅ **源码确认**

`wq_engine.py:274`

```python
n_sub = max(1, int(np.max(u_now) * dt_s / dx) + 1)
```

用 `np.max(u_now)` 而非 `np.max(np.abs(u_now))`。反向流时 `np.max` 可能为负 → `n_sub` 算成 1 → CFL 保护失效。

同文件 `:237` 注释明写"插值流速 (保留方向, 不用 np.abs)"，说明**有意支持反向流** —— 故这是实现漏了。

当前流速约 0.06 m/s 触发不到，属潜伏。

### B.8 连续方程遗漏水面宽 `B_mid` ✅ **实测**（首轮已报，此处存档）

`pure_py_hydro.py:112-117` 的连续性方程系数无 `B_mid`（该变量算出后从未使用）。
实测残差达蓄水率的 103%。补 `B_mid` 的实验已回滚（残差不变且破坏 Newton 收敛）。

### B.9 卫星测宽存在结构性假阳性 ✅ **源码确认**

`satellite_width.py:257`

```python
dark_threshold = np.percentile(gray, 30)
water_mask = gray < dark_threshold
```

**总是**把最暗的 30% 像素判为水体 —— 即使图里根本没有水，也必然"检测出"一条水带。
`confidence`（`:160`）只由有效样本数与变异系数决定，**不反映是否真的检出了水**。

后果：该"实验性"功能在纯陆地影像上也会返回一个宽度值，且带有中等置信度。

## D. 最后三个文件的发现（已全部通读）

### D.1 `river_model/hecras_bridge.py`（465 行）

**模块 docstring 是诚实的**（`:298-303`）：

> 当前 HEC-RAS 7.0 非恒定流 plan 格式未完全兼容 — 只跑稳态流初始化。
> 非恒定流结果由 hydro_engine.run_hydrodynamic() 降级到纯 Python 求解。

也就是说模块**自己声明了只做稳态**，但 `hydro_engine.detect_engine()` 未尊重该声明，
直接返回 `"hecras"` 就把非恒定工况也送了进去 —— 正是已修复的 2.7 的根因。
**声明是对的，调度层没照做。**

其余确认项：
- `:307` `tempfile.mkdtemp` 后无清理 —— **临时目录泄漏已实测复现**（TEMP 下有两个完整 HEC-RAS 工程目录）
