## 2. N01 示例文件

新增：

```text
data/samples/
  manifest.json
  README.md
  S01_仿真_正常背景.csv
  S02_仿真_单源持续排放.csv

  S06_仿真_正常水体加仪器异常与缺测.csv
scripts/prepare_sample_data.py
```

实现要点：

- 只读取原始 Excel 的「仿真走航数据」工作表；不把隐藏真值、污染源参数或说明文字写入 CSV。
- 从原始单元格导出，不从 `load_data` 的清洗/插值结果反推；保留原始行顺序、时间字符串、坐标、有效读数和空单元格。
- 每份 CSV 实测 1801 行、12 列，约 143—144KB；总大小约 0.9MB（按 manifest 实际大小）。
- S06 原始氨氮/溶解氧各有 24 个缺测；CSV 保留空单元格；生产加载器生成 24 个非原始观测标记，并另行插值。
- `.gitattributes` 将 `data/samples/*.csv` 标记为 binary，防止 Git 换行转换改变 manifest 哈希。
- manifest 由实际 CSV 字节生成：ID、标题/用途、文件名、`data_kind=synthetic`、版本（哈希前缀）、SHA-256、字节数、行数/列、时间范围、WGS84 坐标系、来源、无视频、使用限制、字段单位、缺测规则。
- 六份原始 Excel 保留在开发工作区；首批交付包只带 CSV/manifest/README。原始 Excel 未纳入 Git，因此干净 CI 副本无法重做逐单元格 Excel 对照；本机已做该对照。

本机原始对照结果：

- 六份 CSV 与 Excel 的行数、列顺序、首末时间字符串一致；
- 经度/纬度/氨氮/溶解氧逐值比较一致；零值与缺测数量一致；
- S06 缺测数量为 24/24；生产加载器保留 `__observed_*` 区分。

## 3. N02 接口与前端

新增/复用：

- `backend/sample_catalog.py`：只按 manifest 白名单读取；拒绝目录穿越、绝对路径、非 CSV、非“仿真”文件名、符号链接、超大文件；实际字节 SHA 校验；清单损坏/重复 ID/哈希不符作为 503 资源错误，不返回空列表。
- `backend/data_service.py`：上传和示例共用 `parse_monitoring` / `apply_monitoring`，沿用生产加载器与既有清洗/身份规则。
- `backend/routers/data.py`：
  - `GET /api/data/samples`：只读元数据，不建项目、不加载数据。
  - `POST /api/data/samples/{sample_id}/load`：请求包含当前项目、分析/结果版本、`detect` 和可选的 `river_form`；版本不符 409，未知 ID 404，资源错误 503，参数错误 422。
  - 解析候选在切换前完成；先保存当前项目，再创建独立演示项目并应用；保存失败不切换。
  - `detect=true` 在服务端运行基础阈值筛查；筛查失败仍返回“数据已载入 + 检测未完成”，不回滚数据。
  - 示例项目写入 `df.attrs['sample_meta']`（ID/版本/标题/来源）并随项目快照保存；`/api/data/status` 返回 `sample_meta`。
- `frontend/src/components/DataPanel.vue`：空数据时突出“试用仿真示例”，示例列表来自接口；显示标题、场景说明、仿真身份、1801 条、仅监测表；提供“载入”和“载入并检测”；载入中/失败/重试/保存切换提示；未提交的上传文件不会被示例操作静默丢弃。
- `frontend/src/stores/session.js`：`loadSamples` 缓存目录；`loadSample` 携带当前项目和版本，成功后采用服务端独立项目状态；示例载入失败保留当前列表和选择。
- 前端类型/契约：`SampleInfo`、`SampleList`、`SampleLoadRequest`、`SampleLoadResponse`、`SampleDetection`；契约导出加入示例列表和载入真实响应。
