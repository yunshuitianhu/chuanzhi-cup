# 交付包与隔离迁移验收

## 打包

先验证并提交源码，再构建前端，执行：

```powershell
python scripts/package_delivery.py --output work/delivery.zip
```

目标必须是新文件。脚本从Git HEAD读取源码，加入构建清单所列的前端资源；存在未提交源码或未跟踪文件时拒绝打包（`work/`、用户项目、`.rag_index/`、`仿真数据/` 等运行目录除外）。运行向量缓存不随包提供，也不打包个人项目或仿真资料目录。归档若发现被跟踪的`.env`、`.mcp.json`等本机配置则拒绝。

`delivery-manifest.json`记录源码提交和各文件SHA256，接收人可核对文件完整性。前端来自本机已经构建的dist，构建前必须确认源码已提交；清单证明字节内容，不单独证明构建可复现。

解压到新目录后，按README用Python 3.11+（本机以3.14.0验证）安装锁定依赖，执行`python scripts/serve_web.py --check`后启动。已有构建，无需接收电脑启动Node/Vite。RAG索引和嵌入模型缓存需按统一启动说明另行准备。需联网的依赖安装、模型下载与API调用应提前安排。

## 无密钥基础流程验收

在无`.env`和`.mcp.json`的解压副本目录运行：

```powershell
python scripts/verify_delivery.py --output-dir work/delivery-validation
```

输出目录必须不存在，脚本使用隔离项目库，不改接收人的已有项目。它会生成180行公式示例CSV并通过实际API导入、检测、初始化理想河段、恒定流水动力与污染情景、保存和导出，然后在新的独立Python进程中恢复、比较数据/检测/模型数组、导入为新项目并再次导出。

示例无经纬度，不对应任何真实河流。CSV中的公式波动与独立手工情景没有建立物理拟合关系；它只检查导入、分析和迁移流程，不能用于计算正演或反演精度。单点DO=0用于确认有效零值保留。

输出`演示_仿真_非实测.wqproj`可从网页左侧“导入项目包”打开；包括数据、筛查和可播放的理想情景，无真实地图点、视频或AI生成报告。不要把离线示例作为现场监测成果。

验收子进程清除三类服务密钥，禁止requests/httpx对外HTTP传输。实际核实无密钥Agent给出未配置提示，RAG无本地索引显示不可用。它使用真实FastAPI/ASGI接口和内核，未启动真实浏览器或付费模型。

## 验收边界

干净源码副本与独立进程重启不等于另一台电脑完成依赖安装。结果必须说明所用Python、已有依赖环境、是否进行异机安装。Q01负责真实监听和浏览器启动，Q02负责包与迁移；RAG检索质量、在线模型和外部查询失败专项分别由后续任务负责。现场准确率另需真实标签。

## 2026-10-22实际结果

已在Git归档与构建产物组成的独立副本中验收；Python 3.12.14，复用本机已安装依赖。180行公式仿真完成导入、检测及手工模型，两次独立进程重启后24个模型数组、数据和检测内容一致，附件重新物化到新目录且内容哈希一致。导入保留原项目并生成新ID，重导出成功。无密钥Agent与无索引RAG按实际缺失状态返回。
