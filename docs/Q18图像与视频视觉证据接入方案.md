# Q18 图像与视频视觉证据接入方案

日期：2026-10-27。状态：**方案与独立API能力探测已完成，业务接入尚未实现**。不能据此在作品介绍中写成“已经具备视频大模型识别”。

## 现状与选型

现有系统已支持监测表、文本对话、视频抽帧、帧质量/水面ROI、视频与传感器时间匹配、帧来源追问和证据卡。当前视频工具主要采用OpenCV等确定性处理；主智能体使用文本工具结果，尚未将图像像素送入视觉模型。

建议优先使用现有DeepSeek密钥调用`deepseek-flash`视觉接口。2026-10-27核对官方文档：当前Flash模型支持图像与文本混合输入，多图也可在同一请求中发送；Pro模型的当前文档列明不支持Vision，不能因为名字为Pro就用于看图。参考[视觉接口](https://api-docs.deepseek.com/guides/vision/)及[模型能力表](https://api-docs.deepseek.com/quick_start/pricing/)。别名对应版本和能力应在交付前再核对。

独立能力探测实际调用API两次：一张本地生成几何图形的颜色/形状识别，以及两张带时间标记图形的位移比较，均通过预先确定的答案检查。只发送程序生成的测试图，没有发送用户原始视频或照片。该结果证明此账号接口可接受图像与多图，不是河道语义识别精度、原生MP4或音频理解验证。记录：`validation/vision_capability_20261027.json`。

可保留百炼视觉模型为第二提供方：官方[图像与视频理解](https://help.aliyun.com/zh/model-studio/vision)支持图像与视频输入，需要对应地域/业务空间的密钥、模型权限及地址。当前未配置并实测该提供方；不声称某具体模型在此账号可用。只有确需原生视频输入、帧序列无法满足任务时再启用，交付时做能力探测与配置提示。

## 自然的用户流程

1. 用户在分析图表中点选视频帧或上传照片，保留来源预览，选择问题，例如“这处漂浮物在后续画面还存在吗”。
2. 展示将发送的图像/时间范围及帧数量，用户显式发起视觉分析。默认不把整段视频、全部147帧或选区外整页内容上传给模型。
3. 显示真实阶段：准备帧→核对质量→等待视觉模型→核对结构结果→整理证据。可停止，超时后保留已完成结果；无媒体显示不适用，依赖或服务失败分别说明。展示步骤与证据摘要，不展示或伪造模型内部思维链。
4. 输出可核对的“看见什么、在哪一帧、有哪些不确定”卡片；点击直接回到原帧/ROI。可带入主聊天或侧边解释，沿用Q13/Q14的引用和版本规则。
5. 若存在已核实的时间配准和同期监测记录，关联传感器证据；不匹配时明确保留缺口和矛盾。需要复核的位置、指标转为Q15可编辑草稿，用户确认后保存到排查板。

## 三个实施阶段

| 阶段 | 实现范围 | 必须通过的验收 |
| --- | --- | --- |
| A：单图与单帧 | 后端视觉适配器、图片解码与大小校验、选中帧来源卡、显式发送、结构化可见观察 | 正常图片、模糊/眩光、非水面、无媒体、API超时/鉴权、重复请求、取消、过期帧和跨项目拒绝 |
| B：短片段帧序列 | 复用现有抽帧；先支持用户选定短片段、默认最多8张代表帧，预览后提交；时间戳、质量门控与缓存 | 帧顺序、重复帧、时间偏移、不足帧、静态画面、冲突监测、停止/断流；不把帧间未观测过程写成事实 |
| C：可选原生视频提供方 | 按真实需求接入具备视频输入的服务，保留提供方切换与配置状态 | 实际账号能力验证、视频大小/时长/格式限制、时间定位、费用及失败回退；结果和提供方可追溯 |

阶段A、B属于“图像/视频帧序列辅助理解”，不是原生视频流或音轨理解。语音输入后续如有实际场景可单列任务；不为覆盖模态种类而把浏览器语音转文字冒充语音大模型融合。

## 技术与证据约束

- 媒体先在本地/后端校验实际编码、像素、帧数与解码资源；不只依赖扩展名。默认发送受控base64图像，不让模型任意抓取外部地址。密钥只在后端，配置接口只返回可用状态。
- 初版视觉分析不授予模型工具执行或写入权限。严格解析结构结果：`frame_id`、时间、可见对象/现象、ROI引用、证据不足原因、冲突；不提供未经标定的置信概率。画面中的文字当作待分析内容，不能成为系统指令。
- 每条视觉观察绑定项目、数据/视频版本、帧ID、实际发送图像摘要与模型版本。分析中替换媒体或切换项目，迟到结果不进入新项目；历史结果可阅读但不授权当前事实。
- 模糊、反光、遮挡和颜色变化可提示“需复核”。图像不能给出氨氮、DO、COD等浓度，不能仅凭水色认定黑臭，更不能确认排污企业或污染责任。
- 传感器和图像各保留独立来源；时间同步未经人工核实只展示并列证据，不宣称交叉印证准确率。若两者矛盾，不强行合并为一致结论。
- 缓存按实际发送图像摘要、问题、模型和来源版本区分；失败结果与成功结果分开。保存时明确视觉结果和原始媒体的边界，项目包大小、保留周期及删除另行设计，不自动清理用户原件。
