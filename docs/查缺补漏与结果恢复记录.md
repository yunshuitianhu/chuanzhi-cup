# 查缺补漏与结果恢复记录

2026-10-18。本轮检查检测、视频交叉印证、项目持久化和页面的数据一致性。没有修改河道几何、水动力求解器、反应参数或原始污染指数公式。

## 已复现并修复

| 问题 | 原行为 | 当前行为 |
| --- | --- | --- |
| 替换视频清空模型 | 视频上传成功调用全量分析重置，检测、河道配置和模拟一起丢失 | 仅撤销视频相关结果和报告完成标记，保留监测表、检测、模型和历史对话 |
| 只能连同监测表上传视频 | 侧栏必须选择新监测表，按钮才可用；追加视频会先重载监测表 | 已有监测表时允许单独加载视频，成功后清除文件选择，防止重复上传 |
| 刷新后结果面板为空 | 技术页检测和交叉印证各自使用临时局部变量，未读取项目缓存 | 新增只读结果接口，启动/打开项目时恢复，页面读取同一份状态；零预警也显示结果和说明 |
| 数量不变时图表不更新 | 页面主要监听点数，检测结果改变而数量相同时继续显示旧图 | 增加进程内派生结果标记，刷新地图、时间序列和面板；不会使物理模型失效 |
| 请求乱序混入旧结果 | 较早请求可能晚于新请求返回 | 按请求、项目及数据版本丢弃迟到结果；同一客户端重复提交也会被拦截 |
| 非法交叉印证参数 | 字符串可能报500；窗口0被悄悄替换为30；小数被截断 | 严格验证类型、有限数与正窗口；支持负偏移及小数秒，失败保留旧结果 |
| 常数序列相关性 | Pearson返回NaN，接口JSON序列化报500 | 常数、样本不足和非有限结果说明原因，不生成伪造相关系数 |
| 非有限输入再次引发500 | 构造422响应时，错误详情里的NaN/Infinity仍无法序列化 | 统一清理校验错误详情中的非有限数，返回合法JSON和422 |
| 旧报告被当作当前结果 | 重算后旧完成标记和部分证据仍在 | API和Agent共用结果更新方法，撤销旧摘要/完成标记，检测更新撤销依赖旧热点的外部线索；保留历史正文并提示待重新生成 |
| 视频指标名称夸大 | 以传感器阈值筛查为参照的比例显示成视频准确率 | 改为“视频预警符合率”“传感器预警的视频覆盖率”，注明没有人工真值；旧项目数值兼容读取 |

视频解码还会跳过无法读取、缺少字段、非法时间的帧，并分别报告总帧数、有效帧数和无效帧数。相关性结果明确为探索性分析，窗口可能重叠，p值未作多重比较校正，不用来证明因果。

常数输入的处理依据与[SciPy官方Pearson文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.pearsonr.html)一致：这类相关系数未定义。没有把NaN改成0，或编造显著性。

## 兼容与行为说明

`GET /api/analysis/results`只读取已经计算的结果，不触发视频解码、检测、外部查询、模型运行或LLM。缓存JSON无法解析、顶层类型错误或包含非有限数时返回可读说明，不影响其余项目内容。

`results_revision`是进程内的缓存标记，不写入项目包，旧包仍可直接恢复，无需数据库迁移。打开项目原有的数据版本更新机制继续生效。原来的视频比例键为旧调用方保留；综合报告改用参照表述。历史报告不会自动改写，更新结果后状态为`stale`，自动分析正在运行时不会被这一机制中断。

技术页还会提示旧算法结果需要重新检测。国控介绍改为按本次实际来源、监测时间和状态说明，去掉未动态核实的覆盖数量/更新频率承诺。

### 真实样例与保存恢复

在隔离项目库读取用户项目副本：1805条监测数据、147帧原视频、现有50断面模型。147帧全部匹配，12个相关系数均为有限数；检测仍为1230个阈值预警点、10簇。随后使用实际编码的3秒合成小视频测试上传替换，得到3帧，交叉印证清空，检测和62个模型数组保持一致；项目保存后清除内存再恢复仍一致。合成小视频只用于隔离验证，没有替换用户视频。

更新服务前保存两个绑定会话，保留旧8002服务，仅更新当前8003。当前“111”项目用原数据/原147帧重新计算检测和交叉印证，保存为版本10。5173代理可读取恢复结果，非法输入返回422且不会修改结果。版本9与10从磁盘回读比较：监测表、视频帧、历史对话、62个模型数组一致，氨氮/DO/CBOD三组播放数据哈希也一致。

检查涵盖源码、算法、API、保存恢复、组件函数、SSR和构建；未进行真实浏览器视觉验收。

## 尚未完成的验证

DO/pH工程指数口径、浊度经验参考值仍需后续标准化审查。本轮没有宣称其已获得现场校准，也不依据视频与传感器的一致比例估算真实准确率。缺少人工复核和仪器资料时，仍只能开展规则及受控场景验证；完整水体定级与污染责任认定不属于当前两指标筛查能力。
