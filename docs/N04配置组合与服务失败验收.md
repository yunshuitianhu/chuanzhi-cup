## 1. 实际入口与能力矩阵（N04-A01）

### 1.1 代码入口

| 能力 | 主要入口 | 当前实现 |
| --- | --- | --- |
| 配置状态 | `GET /api/config`（`backend/routers/system.py`） | 只返回 `keys`、`key_state`（configured/verified/notice）、目标水质等级；不返回值 |
| 前端配置展示 | `frontend/src/App.vue`、`utils/keyState.js` | “未配置 / 已填写（未验证）”；已填写数 `n/3` |
| 模型失败文案 | `backend/agent/error_text.py` | 认证、额度/频率、权限、超时/网络、5xx 分类；主循环和侧边线程都做密钥脱敏 |
| 示例与筛查 | `GET /api/data/samples`、`POST /api/data/samples/{id}/load` | 六例、质控、阈值筛查、图表；不依赖 LLM Key |
| 手工恒定流 | `POST /api/river/init`、`POST /api/river/hydro` | 内置一维恒定流求解器；不需要 LLM Key |
| 本地 RAG 状态/检索 | `GET /api/rag/status`、`POST /api/rag/search` | 按依赖、索引读取、索引构建、模型加载、实际检索分阶段；不依赖 LLM Key |
| 国控站点 | `GET /api/stations` | 实时失败时返回离线目录/背景，并标注是否含实时监测值 |
| 高德底图 | `GET /api/maps/amap-static` | 缺 Key 返回 503；上游失败 502；密钥不进入响应 |
| 星图瓦片 | `GET /api/maps/starcloud/{z}/{x}/{y}` | 缺 Token 返回 503；权限/额度/网络分别提示 |
| 备用底图 | `TraceMap.vue` 的 Esri/OSM | 公网可达时可用，不保证断网；不统称卫星影像 |

### 1.2 与任务要求对照后确认的差异

| 编号 | 发现 | 处理 |
| --- | --- | --- |
| N04-A02 | `/api/config` 已返回 `verified:false`，但前端和后端都没有“服务健康已验证”的写入路径 | 保持 `verified:false`；文案明确“已填写不等于已验证”，不新增健康状态 |
| N04-A03 | 配置布尔值容易被理解为“服务可用” | C06 验证：三类 Key 全为真时 `verified` 仍为假；错误分类以本次调用结果为准 |
| N04-A04 | 无数据时示例区已 `prominent`，但侧栏配置折叠；`ChatView` 已提示可先用示例 | 保留现布局，不增加强制引导 |
| N04-A05 | 前端不要求三个 Key 齐全才进入页面 | C01 验证：全无 Key 仍可列六例、载入 S01、筛查和出图 |
| N04-A06 | README 与 `.env.example` 已说明模型名/Base URL 固定 | 保留；没有新增供应商切换器 |
| N04-A07 | README 能力表把 Esri/OSM 与需要 Key 的服务混在一行 | 已拆成两行：国控/星图/高德需要对应 Key；Esri/OSM 只需公网可达 |
| N04-A08 | 页面“重新检查配置”容易被理解为热加载 `.env`；README、`.env.example`、交付说明未写重启规则 | 前端改为“刷新配置状态”并注明修改 `.env` 后需重启；三处文档同步；C08 验证 `load_env` 只在显式调用时读取 |

本轮另外修复了两个在受控矩阵中复现的问题：

1. **失败后问题草稿被清空**：`ChatView` 在发送前清空输入，HTTP 500/流中断后不恢复。
   现在仅在输入仍为空时恢复原问题，不覆盖用户新输入；引用上下文保持，重试入口可用。
   附件字节的保留由既有媒体回归覆盖，新增用例没有单独上传真实附件。
2. **侧边线程错误可能回显密钥**：主循环对 `model_error_message` 做了脱敏，侧边线程只拼接原文。
   现在侧边线程同样经过 `_scrubber()`；新增受控异常回归。
