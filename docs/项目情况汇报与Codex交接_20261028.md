## 10. 已知坑（Codex 最容易踩）

1. **必须用带 `water_quality_mcp.src...` 的全路径导入**；短路径可能加载到 `D:\aiRAG` 的另一份代码。
2. 会话靠 `X-Session-Id`，后端必须在响应头回传；测试不要手动替客户端带 id 写用例。
3. 开发 Vite 只监听 IPv6 `[::1]:5173`；生产 `serve_web.py` 监听 `127.0.0.1`。
4. curl/urllib 默认走本机代理，访问本地服务要 `--noproxy '*'`。
5. 端口残留监听很常见；换端口比杀进程快。
6. 示例 CSV/manifest 是字节级契约，不能用 `load_data` 结果反向生成；不要手改。
7. `prepare_sample_data.py` 默认源是 V1；不要用 `--force` 把当前 V2 覆盖回 V1。
8. 当前 `data/samples` 是 V2；`tests/test_sample_catalog_regressions.py` 检查坐标到 V2 路线 <10m。
9. 打包器只认已提交源码；`work/` 被忽略，ZIP 需单独发送；ZIP 哈希不写入包内。
10. `.rag_index/chroma.sqlite3` 每次检索都会被写；跑完 RAG 后如需提交，先停服务并 `git checkout -- .rag_index/chroma.sqlite3`。
11. 测试必须隔离项目：`WQ_PROJECT_HOME` 指向临时目录；浏览器脚本不要写进用户默认 `data/projects`。
12. 干净 CI venv 没有 RAG 依赖；要测 RAG 必须用完整环境。不要把 ChromaDB/PyTorch 装进干净 CI venv。
13. 接口不得返回本机绝对路径/密钥；`/api/config` 只返回布尔和提示。
14. 字号已全站 +2px；不要为了排版再把某些说明改回 10/11px。
15. Q16 的失败重试不是成功重试；不要把“部分完成”写成“已完成”。
