# 仿真示例 V2 路线与坐标修复

> 日期：2026-10-28
> 触发：用户指出 `data/samples` 的仿真数据经纬度有问题，无法准确定位河道位置。
> 结论：运行时一直读取 `data/samples`，但其中六份 CSV 仍是 V1 静态地图描线；V1 路线是跨城区的对角线，不在水面。现改用仓库已有 V2 卫星水面定线数据，重新生成六份 CSV 与 manifest。

## 1. 诊断

| 检查 | 结果 |
| --- | --- |
| 运行时数据源 | `backend/sample_catalog.py` 只读 `data/samples/manifest.json` 白名单；`仿真数据/` 只在转换脚本和文档中出现，不在运行时读取 |
| CSV 与旧 Excel | 六份 CSV 的坐标与 `仿真数据/S01—S06*.xlsx` 的 V1 工作表逐值一致 |
| 路线几何 | V1 的 S01 从 `118.7622,32.0385` 斜向 `118.7970,32.0237`，横穿南京城区；卫星图上不在秦淮河水面。S03/S05 同样横穿成都、杭州城区 |
| 坐标顺序/类型 | 经纬度列、顺序和数值类型正确；不是 lon/lat 互换，也不是未解析的文本 |
| 已有修复 | `scripts/generate_synthetic_monitoring.py` 已有 V2 路线（提交 `6c0e403`），按星图卫星可见水面重新定线；旧文档明确 V1 停用于地图验证 |

因此问题不是“导入了错误的 Excel”，而是 **data/samples 中的 CSV 仍是 V1 路线**。只改坐标转换或只改导入路径都不能解决。

## 2. 修复

1. 用仓库脚本生成 V2 中间数据到新目录，不覆盖 `仿真数据/`：
   ```bash
   python scripts/generate_synthetic_monitoring.py --output work/synthetic_v2_20261028
   ```
2. 新增 `scripts/materialize_sample_workbooks.py`，把生成器的 `S??_workbook_payload.json` 写成带「仿真走航数据 / 数据说明」工作表的 Excel；输出到新的 `work/sample_source_v2_20261028`，不覆盖原始 Excel。
3. `scripts/prepare_sample_data.py` 增加 `--source-label` 与 `--version-prefix`，从 V2 工作簿重新导出 CSV 和 manifest：
   ```bash
   python scripts/materialize_sample_workbooks.py \
     --input work/synthetic_v2_20261028 \
     --output work/sample_source_v2_20261028
   python scripts/prepare_sample_data.py \
     --source-dir work/sample_source_v2_20261028 \
     --output-dir data/samples \
     --source-label "scripts/generate_synthetic_monitoring.py v2（卫星水面定线）" \
     --version-prefix v2 --force
   ```
4. `data/samples/README.md` 改为 V2 说明：路线按卫星可见水面人工近似定线，不是测绘中心线；V1 Excel 仅作历史资料。

## 5. 边界与未做

- V2 路线仍是**人工近似定线**，不是测绘中心线，不承诺定位精度；南京/成都/杭州只是地图参考，杭州河名未核实。
- 样本仍是合成数据，不是现场实测、当地污染事实或污染源真值；热点数量不等于污染源数量。
- 原始 `仿真数据/` 的 V1 Excel 未被覆盖，仍作历史资料；V2 工作簿在 `work/`，不进入 Git 或交付包。
- 旧浏览器验收记录中的 `v1-…` 版本号和截图对应 V1，已被本次数据更新取代；不能把旧记录当作 V2 结果。
- r2 交付包 (`4cc2a1a`) 生成于本次样本更新之前，**不包含 V2 CSV**；需要重新打包并记录新哈希。
- 未重新执行完整 DeepSeek/地图/RAG 在线验收；本次只改示例坐标/数据版本与相应回归。
