## 1. 实现

### 1.1 后端

`POST /api/vision/observe` 新增 `kind='video_frames'`：

- 请求：`frame_ids` 2—8 个、`video_revision`、可选问题；帧编号去重、非负；服务端按帧号加载，并校验 `time_sec` 非递减；时间缺失或倒退直接拒绝，避免倒序发送。
- 逐帧复用 `video_frame_image` 的版本、解码与质量校验；`invalid` 或 `manual_exclusion` 帧拒绝整段发送，`needs_review` 帧保留质量提示。
- 模型输入包含每帧的服务器编号、帧号和相对时间；提示只比较已发送帧，不推断帧间未展示过程。
- 严格解析：`frames` 必须与发送帧数一致且 `index` 从 1 到 N；`changes` 的 `from/to` 必须有效且 `from < to`；未知字段、空白观察、错序帧均拒绝。
- 所有帧像素 SHA 相同则返回 `static_sequence=true`；若模型仍返回帧间变化，拒绝结果，避免把静态画面写成变化。
- 缓存只保存模型解析内容，键为有序图片 SHA + 问题 + 模型 + 有序帧号/相对时间标签；命中时按本次已校验帧重建来源、帧号、时间、质量与作用域。
- 同样的作用域/来源 post-check 和 `finish_reason='stop'` 门禁；失败不写缓存。
- 若视频复核区已人工确认同步（`sync_confirmed`），按 `time_offset_sec`/`time_window_sec` 返回每帧时间窗内原始监测值的并列摘要；未确认同步时明确不关联，窗口无记录时保留缺口，不自动判定一致或冲突。

### 1.2 前端

新增 `VisualSequenceEvidence.vue`，接入视频页：

- 选择起始帧（1 基）和帧数 2—8；点击“预览选中帧”才读取图像，显示缩略图、帧号、时间、帧质量和不可发送标记。
- 必须完成预览且不含无效/人工排除帧，才能点击“发送序列给视觉模型”；选择、翻页、挂载都不会自动发送。
- 支持停止等待、失败提示、工作区/项目/版本变化丢弃迟到结果。
- 结果展示逐帧观察、直接可见变化、不确定说明、未看到内容、静态序列警告、传感器时间窗并列摘要和固定限制；不显示 base64，不写报告/排查板。

## 4. 未完成/限制

- 时间偏移：已按视频复核设置返回时间窗摘要；未人工确认同步时仍不关联，不能据此确认同期监测。
- 传感器冲突：已并列展示时间窗原始监测值，但未自动判定与视觉观察一致/矛盾；需人工核对。
- 选择方式：当前只支持连续起止范围；后端可接受任意排序帧列表，但 UI 未提供非连续选择。
- 质量门禁：只拒绝 `invalid`/`manual_exclusion`；`needs_review` 仍可发送并显示提示，未做真实模糊/眩光/非水面负例评估。
- 真实模型只跑了一次两帧受控纹理；未做多帧真实性/定位准确率、浏览器视觉走查或原生视频验证。
- 不宣称帧间移动、扩散、排放过程或污染责任；结果不持久化。
