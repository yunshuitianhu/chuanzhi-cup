# 项目保存与迁移说明

日期：2026-10-18。第一阶段“通用河流项目管理”已实现；不改变既有恒定流模型的适用范围。

## 是否需要部署数据库

使用SQLite。它随Python提供，不需要额外安装数据库服务、申请云数据库或启动Docker。

默认目录结构：

```text
data/projects/
  projects.sqlite3       项目索引、版本记录、会话与项目绑定
  <项目ID>/
    <随机快照ID>.wqproj   不可变版本包
  runtime/<随机ID>/       每次工作区独立的模型图表/导出文件
```

可在启动后端前设置环境变量`WQ_PROJECT_HOME`，指定有写权限的数据目录。路径仅由本机启动配置提供，导入包不能指定目标磁盘路径。SQLite文件及整个运行目录均不入Git；原RAG数据库独立存在，本次未修改其已有工作区变更。

数据库管理项目名称、最新保存版本、时间和快照位置；较大的表、数组、视频抽帧和附件在快照文件中。目前保留保存版本，尚未提供图形化历史回滚或清理；频繁保存大量视频帧会增加磁盘占用。

## 页面操作

1. 在侧边栏填写项目名称，点击“当前内容另存为”，将当前监测数据和分析保存为独立项目。
2. 修改数据、等级或运行模型后，点击“保存项目”。保存的内容才能保证在重启后恢复。
3. “新建空项目”会先保留当前项目/临时内容，再进入空白工作区。
4. 从列表选择项目，点击“打开项目”。切换前保存当前工作，随后恢复目标数据、配置、历史和模型；清除原项目的前端缓存。
5. “保存并导出”先保存，再下载`.wqproj`包。接收电脑打开同版本程序并选择“导入项目包”，建立新项目副本，不覆盖已有项目。

未命名临时会话在切换前会保存为带时间的未命名项目。重复打开同一项目不会自动丢弃当前未保存修改。两个会话同时修改同一项目时，版本过期的一方会收到冲突提示，可“另存为”保留自己的修改，不能静默覆盖较新版本。

浏览器保留会话ID时，后端首次请求从SQLite绑定恢复最后保存项目；换浏览器、换电脑或清空浏览器存储后，仍可从项目列表选择。运行中任务不跨重启续跑，多worker共享内存会话尚未实现，当前请只启动单worker。

## 保存的具体内容

| 内容 | 保存与恢复范围 |
|---|---|
| 监测数据 | 处理后的完整DataFrame、时间/时区、列类型、索引、缺测及实测标记、质量元数据；零值保留 |
| 分析 | 黑臭检测表及原JSON、交叉印证、综合摘要、图表说明、国控查询证据及时间 |
| 对话 | 页面历史与工具对话上下文；配置中的密钥不会打包，已知密钥文本也作脱敏 |
| 河段 | 用户已应用配置、参数来源、断面几何、运行版本与情景参数 |
| 数值结果 | 水动力及水质数组、质量/反应核算和来源元数据；不通过重新估算来“重建”数值 |
| 模型附件 | 本次工作区生成的模型PNG、动画HTML及JSON/CSV导出；恢复到接收电脑的独立目录 |
| 视频 | 已提取JPEG帧及相对时间；不包含原始整段视频 |
| 页面草稿 | 河道页表单；若未应用的几何/边界草稿与已保存计算不同，要求重新初始化/运行对应阶段 |

原Excel工作簿和原视频不在包内；需要保留原始采集文件时请另行归档。迁移包保存的是已处理监测表和计算记录。外部底图、实时国控与LLM能力仍需接收电脑的网络和密钥；已存结果与手工情景不依赖开发者本机路径。

## 保存一致性和导入检查

- 写入新快照、刷盘、回读校验后，才在SQLite事务中更新当前版本指针。失败时旧版本不变，内存中当前内容保留。
- 包内清单记录格式版本、保存时间、Python/NumPy/pandas版本，以及每个文件的大小和SHA-256。
- 数组使用无pickle的NumPy数据；只恢复固定白名单的数据类型。检查路径、文件列表、版本、哈希、展开大小、数组形状及基本河段参数。
- 导入不执行包内代码、不按包内路径解压到任意目录。损坏/不支持的包在替换当前会话前拒绝。
- 每个工作区模型输出目录独立；matplotlib绘图互斥，避免不同项目共享图文件或绘图全局状态。
- 若已保存快照损坏，显示恢复错误，保留损坏文件；可以打开其它完整项目或导入以前导出的备份。导入仍创建新ID。

单包限制256MB，展开内容最大512MB，最多4096个条目。项目包为明文数据包，应按采集数据的共享范围保管；不提供用户登录、团队权限或加密云同步。
