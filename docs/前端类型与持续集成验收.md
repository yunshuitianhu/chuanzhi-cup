# Q08 前端类型与持续集成

日期：2026-10-23。当前范围是关键边界的渐进类型检查与离线 CI，非全站 TypeScript 迁移、在线模型准确率或现场验收。

## 实现

- `frontend/tsconfig.json` 开启 TypeScript strict、checkJs、noEmit。先覆盖 `api/client.js`、`stores/session.js`、`utils/agentStream.js`、`utils/projectRestore.js`，用 TypeScript 契约与 JSDoc 检查现有运行代码，保留现有 JavaScript 导入路径。
- 核心契约覆盖会话、配置、项目/模型恢复、河道请求、分析缓存、Agent 进度及 SSE 判别联合。导出为 Blob；当前河道请求不接受潮汐幅度或 DO 排放类型。数值范围仍由现有服务端校验负责。
- SSE JSON 在外部边界检查字段和终态，错误字段不进入消费者，未知扩展事件不充当完成。保留 UTF-8 分片、409 有限重试和断流不误报成功的行为。
- 临时会话导出前检查当前项目，显示“请先保存项目后再导出”，避免访问空项目 ID。HTTP 422 畸形错误项保留原 HTTP 状态，不再因错误项为空覆盖原错误。
- `tests/types/core.contract.ts` 包含编译期反例：空项目、错误字段/等级/模型参数、Blob 与 JSON 混用、错误终态和状态赋值。约束退化为 any 或取消严格空值检查，也会因未使用的 `@ts-expect-error` 失败。
- `scripts/export_frontend_contracts.py` 用真实 TestClient 响应生成 15 份 TypeScript 赋值检查，包括空项目、DO=0、分析缓存、错误历史、初始化/正演后的模型及运行/partial 进度。生成物不提交，不含用户项目或密钥值；模型运行产物也在临时目录。
- `scripts/check_ci.py` 生成 120 行显式仿真 Excel，为旧检查传入实际存在的样本，使用临时项目目录；旧脚本外部 Requests 明确拒绝并走既有降级，不传入真实密钥。
- GitHub Actions 对 push、pull_request 和手动运行触发 Windows/Ubuntu 两个环境。只读仓库权限、固定 Action 提交、取消同分支旧运行；运行 Python 回归、字段/泛化/HTTP/密钥检查、真实后端响应契约、前端类型/测试/生产构建。不需要仓库 Secrets，不使用 `pull_request_target`。

## 复跑

从项目根目录运行（Python 3.12、Node 24）：

```text
python -m pip install -r requirements-ci.txt
python scripts/check_ci.py
python scripts/export_frontend_contracts.py
cd frontend
npm ci
npm run check
```

前端单独检查使用 `npm run typecheck`；完整前端检查使用 `npm run check`。全流程中先导出后端响应，才能包含本次真实响应契约；只运行类型检查不会主动启动 Python。
