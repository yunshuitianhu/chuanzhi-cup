## 3. 原问题与修复思路

### 3.1 进度面板占位

原 `AgentProgress.vue` 的问题不是“历史列表太高”，而是信息层级：

```js
const failureSteps = computed(() => steps.value.filter(step =>
  ['failed','partial','cancelled','skipped'].includes(step?.status) || !!step?.notice))
const historySteps = computed(() => historyOpen.value ? steps.value : failureSteps.value)
```

即使 `historyOpen=false`，所有失败、跳过、取消以及带 notice 的成功步骤仍会渲染在正文上方；标题、统计、说明、最新步骤和“展开历史”按钮也常驻。失败越多、提示越多，占位越高。

`ChatView.vue` 里同时存在：

- `.conversation.has-progress .stream { max-height: calc(100dvh - 530px) }`
- 末尾 `.chat-workspace .stream, .conversation.has-progress .stream { flex:1; max-height:none }`
- 移动端又一组 `calc(100dvh - 570px)`

多组规则互相覆盖，实际可用高度难以解释。

修复后：

- 默认只保留一行状态 + 一行摘要；完整步骤和历史只在“查看详情”抽屉中出现。
- 摘要按实际状态生成，不铺开失败正文。
- 工作区高度只由外层 `calc(100dvh - 122px)`（1023px 以下 104px，600px 以下 96px）确定，正文 `.stream` 用 `flex:1; min-height:0` 吃掉剩余空间。
- 删除 `has-progress` 类及全部 `.stream` 的 `max-height` 常量。

### 3.2 报告失败与最终结果混淆

原页面只有尝试级计数，例如“已完成 18 · 失败 1”，没有表达“失败的这次报告后来成功了”。用户看到“失败 1”和失败的 `generate_final_report` 步骤，容易认为整轮没有报告。

新逻辑按工具名和时间顺序计算：

- **尝试级事实**：每次调用单独保留，不删除、不改写状态。
- **报告最终状态**：以最后一次 `generate_final_report` 为准。
- **恢复关系**：同一轮内，某次失败之后如果出现同名工具的成功调用，则这次失败标记为“后续同名调用已成功”。对报告工具，摘要使用“报告失败后重试成功”；对其他工具，只写“同名步骤已成功”，详情注明“未核对是否同一输入”，避免把不同坐标/关键词/条件的同名调用误判为同一任务重试。
- **未恢复失败**：失败之后没有同名成功调用的尝试，按数量显示在紧凑摘要中。

报告状态对照：

| 最后一次报告尝试 | 紧凑摘要 |
| --- | --- |
| 没有调用报告 | `未生成报告`（仅自动分析或确有报告调用时显示） |
| 进行中 | `报告生成中` |
| 成功 | `报告已生成`；此前有失败时追加 `N次报告失败后重试成功` |
| 失败，且此前没有成功 | `报告未生成` |
| 失败，但此前成功过 | `报告未更新（最新一次失败）` |
| 已停止 | `报告未完成（已停止）` |
| 已跳过 | `报告已跳过` |

这条路径仍然存在。页面现在的行为是：

- 如果第一次报告失败、后续模型重新取摘要并成功，摘要显示“报告已生成 · 1次报告失败后重试成功”；
- 如果最后仍失败，摘要显示“报告未生成 / 报告未更新”和“未恢复失败 N”。

也就是说，**页面不再把已经成功的报告显示成失败，但不能阻止第一次失败发生**。要消除这次失败，应在 `backend/agent/loop.py`、`backend/agent/tools.py`、`backend/session.py` 中按交接文档做“报告前显式核对证据版本、最小刷新综合摘要、有限重试、报告/卡片预算”的调度修复。本轮按用户要求未改这些文件。

### 6.2 P1-A：结构化错误（未做，需要后端）

进度详情直接展示服务端 `tool_notice()` 生成的白名单说明。对于“报告前置条件不满足”，当前仍显示：

> 输入、参数或前置步骤不满足要求；请核对数据和相应页面的配置。

本轮没有把它细分为“摘要版本失效 / 缺必填参数 / 无监测表 / 未上传视频 / RAG 缺依赖 / 外部鉴权 / 报告被截断”等结构化错误，因为这需要在 `backend/agent/progress.py` 和 `tools.py` 定义错误码与安全字段。页面只做了两件事：

- 把失败尝试与最终恢复状态分开；
- 在详情中保留失败发生的具体工具和尝试序号。

### 6.3 其他未做项

- **报告产物入口**：没有新增“本轮报告”独立入口。报告正文仍由最终助手消息和“查看本轮数据与工具证据”承载；未实现交接文档 5.2 的“报告作为明确产物、聊天总结链接到产物”。
- **MAX_TURNS=15 预算**：未调整 `loop.py` 的轮次上限或报告/卡片预算。
- **报告流式化**：`report.py` 未改，页面仍显示真实阶段而不是假进度；没有把未完成报告保存为成功。
- **真实在线全流程**：未执行隔离项目 + 原始样本 + 无视频仿真的在线验收。
- **`generate_final_report` 参数契约**：后端 schema 仍要求字符串 `summary`，而报告事实实际由会话重建。本轮未改 schema 或调用说明；如果后续移除/改为可选，需要同步 `backend/agent/tools.py`、模型提示和测试。
- **`step` 快照上限**：`AgentRun.snapshot()` 只保留最近 100 次步骤；如果报告失败发生在 100 次之前，前端无法在详情中还原。页面会明确标注“查看详情（最近100次）”和“最近工具尝试（100 / 120）”，`tool_count` 仍显示总数，但更早的失败尝试不可见。
- **同名工具的输入差异**：前端只有工具名、状态、耗时和 notice，没有参数或输入哈希；因此除报告外，不把“同名后成功”称为“同一任务已恢复”，详情明确写“未核对是否同一输入”。
- **抽屉未锁定 `body` 滚动**：详情自身和历史列表可滚动，遮罩拦截点击；未额外修改 `document.body.style.overflow`，避免与侧栏抽屉的滚动锁互相覆盖。
