## 1. 结论摘要

本轮打通了“选帧/截图 → 服务器读取真实图片 → 模型多模态输入”和“按需只读业务数据”两条链路，并把回答风格、报告抬头和对话页布局按方案调整。

已实际完成的重点：

- 视频选帧与上传/粘贴截图都进入真实 `image_url` 内容块；图片内容不写入 SSE、历史正文或每轮 `full_messages`，按附件/帧重新加载。
- 新增 `get_project_data_catalog`、`read_project_data`、`inspect_visual_asset` 三个只读工具；统计在服务器计算，支持分页、截断状态、版本校验和跨已保存项目只读读取。
- 新增会话媒体层与 `schema_version=4` 项目包：图片随保存、导出、导入、重启恢复；旧 1—3 版项目以空附件兼容；内容缺失/哈希不符/尺寸不符会拒绝。
- 侧边问答接受文字、视频帧和图片附件上下文；侧边可直接上传/粘贴截图并新建图片线程，也可把来源转回主对话。
- 新增共享表达规范，自动分析、自由聊天、侧边和报告共同引用；报告正文先给摘要，服务端确定事实移到末尾“数据与依据”。
- 对话页默认收起分析信息，正文占主要高度；空会话和已选图片的 1280×800、390×844 视口均实测达到目标；短屏展开时使用可滚动抽屉。
- 真实 `deepseek-flash` 完成了生成图、界面截图、受控视频帧、连续帧、产品选帧链路和产品截图链路的图片输入；记录见 `docs/validation/vision_product_20261027.json`。
- 固定 10 个问题的真实模型阅读样例见 `docs/validation/response_quality_20261027.json`；“第38帧”实际映射到内部 `frame_id=37`、`frame_number=38`、185.0 秒。

### 3.4 图片数据流

1. **选帧**：`video_frame` 上下文 → `vision.load_for_context` → `routers/video.frame_bytes` 解码当前帧并缩放到 960px、JPEG → data URL → 用户多模态内容块。
2. **上传/粘贴**：`POST /api/media` → 实际解码、缩放、PNG/JPEG 规范化、SHA-256 → `image_asset` 上下文 → 同一多模态内容块。
3. **模型主动查看**：`inspect_visual_asset` 只返回安全引用和元信息；loop 收集本次 assistant 的全部工具结果后，才追加图片用户消息；单张上限 4、序列上限 8。
4. **持久化**：项目包 `media/<asset_id>.<ext>` + `state.json` 元数据；历史消息只保留上下文卡和哈希，不保存 base64。
5. **失败**：上下文图片读取失败时仍可回答结构化记录，但系统提示和 SSE 明确“不得声称已看到图片”；工具图片解码失败则工具返回错误，不发送图片。

### 3.5 只读业务数据工具

| 工具 | 能力 |
| --- | --- |
| `get_project_data_catalog` | 当前项目或明确指定的已保存项目：数据是否存在、记录数、业务列、时间范围、版本、视频/结果/模型/任务/附件状态。 |
| `read_project_data` | `monitoring_records`、`quality_control`、`black_spots`、`analysis_results`、`video_frames`、`river_model`、`investigations`、`reports`、`external_evidence`、`project_info`；支持时间、指标、数值范围、分页；返回 `returned_count/total_count/truncated`。 |
| `inspect_visual_asset` | 当前视频帧（`frame_id` 0 基或 `frame_number` 1 基）或当前会话图片附件；只返回元信息和 `vision` 引用，由 loop 加载真实图像。 |

跨项目读取只加载已保存快照，不切换当前项目；项目不存在/损坏/版本不符时返回明确错误；没有结果时返回 `status=no_result`，不当作工具执行失败。报告类返回正文摘要与事实计数；综合摘要支持字符偏移续读；河道模型返回已有水位/流量/浓度统计和末尾剖面，不触发重算；应用未保存反演结果时明确标注。

### 4.3 真实模型回答风格样例

记录：`docs/validation/response_quality_20261027.json`

固定问题包括：图片说明、氨氮突升、溶解氧概念、第38帧、正演/反演、能否确认来源、没有视频、只要专业参数、哪些结论是仿真、TimeoutError 含义。

阅读结论：

- 10 个问题均返回 `run_status=succeeded`；普通概念题不再被数据前提阻断。
- “第38帧”样例实际调用了 `inspect_visual_asset`，返回 `frame_id=37`、`frame_number=38`、`time_sec=185.0`，没有错一帧。
- 氨氮突升样例先给结果，再给时间、位置、读数、质控和空间证据；调用工具从 14 个降为 4 个，不再生成正式报告。
- 专业参数样例按要求给出原始字段、版本、统计和记录位置，长度约 1900—2600 字；其他普通问题约 295—755 字。
- 仍然存在长度偏长、个别技术计数进入正文的情况；这是软目标，不能把样例当作逐题专家评审或自动禁词通过。

## 5. 未完成与限制

1. **侧边未加工具循环**。方案原文为“侧边若加工具循环，只给只读白名单”，属于可选；本轮侧边已可直接上传/粘贴图片、共享表达规范和转回主对话，但不执行数据工具，仍保持“不改主报告/任务”的原约束。
2. **跨项目只读图片与部分结果仍未完全开放**。`get_project_data_catalog` 可列出已保存项目的图片元数据，但 `inspect_visual_asset` 只读取当前会话附件/当前视频帧；跨项目图片字节读取未做。报告只返回摘要与事实计数，河道结果只返回统计/末尾剖面；应用没有保存反演结果，`inverse_available=false`。
3. **未验证原生视频输入**。本阶段只做静态图片和带时间戳抽帧序列；模型没有被宣称为“直接理解完整视频”。
4. **完整自动分析/报告未用真实模型逐题重跑**。T05 的报告风格通过单元测试和报告生成器受控调用验证；真实自动分析 SOP、RAG 案例和最终报告正文未在本轮重新做端到端质量评审。
5. **10 题真实模型样例不是专家评审**。没有独立人工标注，也没有现场准确率；回答长度仍是软目标，个别技术计数可能进入正文。
6. **浏览器验收范围有限**。Chromium 桌面/模拟手机/横屏；覆盖空会话、普通输入、图片引用、展开/收起、侧边上传和上传失败重试，但未逐一截图运行中、部分失败、已完成、历史报告六种状态；视频帧复用图片的一行摘要，未单独截图；未验证真实软键盘、辅助技术和其它浏览器。
7. **旧应用不能读新项目包**。项目包升级到 schema 4；schema 1—3 可读并为空附件，schema 4 需要当前版本应用。
8. **未修改 `app.py`（Streamlit）**。本轮只接通 FastAPI/Vue；旧 Streamlit 的工具与页面仍是原实现，不应把本轮图片能力当作 Streamlit 能力。
9. **未改变现场结论边界**。图片、仿真、插值、质控标记、RAG 案例和模型结果仍不能确认污染责任或现场准确率。
